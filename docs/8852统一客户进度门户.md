# 8852 统一客户进度门户设计

## 1. 目标

B 端（企业客户）与 C 端（售前分享的终端客户）的**订单/进度查看**统一使用同一套 **Vue 门户（`b2b-client`）**，由 Nginx 对外暴露的 **8852** 端口承载静态资源，并通过同源的 `/api/` 反向代理访问后端（8851）。

这样：

- 客户只需记住「打开业务发给你的链接」即可，不再区分管理端 Electron/Web（3000）与门户。
- 分享链接中的路径段固定、可文档化，便于运维与 Nginx `try_files` 配置。

## 2. URL 约定

设门户对外基址为 `JEWELRY_PORTAL_BASE_URL`（示例：`http://39.102.213.51:8852`，**勿将真实公网地址硬编码进仓库**）。

| 场景 | 路径模板 | 说明 |
|------|-----------|------|
| B 端客户创建订单后查看 | `{PORTAL}/portal/b2b/order/{accessToken}` | `accessToken` 为 `order_access_links.access_token`（UUID 无横线），与公开接口 `GET /api/b2b/order/{token}` 对应。 |
| C 端售前生成客户进度链接 | `{PORTAL}/portal/c/progress/{viewToken}` | 打开后需 **注册/登录 C 端门户账号**；`GET /api/public/customer-order/{viewToken}/hint` 提供预填信息；进度数据通过 `GET /api/portal/c/orders/{orderId}/summary`（需 `C_PORTAL_CUSTOMER` JWT 且订单已绑定）。 |

末尾路径段在业务上常被称为「订单/任务 id」，技术上为**不可猜测的访问令牌**。B 端创建订单、C 端绑定订单均需先登录门户账号（JWT）。

### 2.1 兼容旧书签

历史链接 `/order/{token}` 仍由 Vue Router **重定向**到 `/portal/b2b/order/{token}`。

## 3. 后端配置

| 配置键 / 环境变量 | 作用 |
|-------------------|------|
| `app.portal.base-url` / `JEWELRY_PORTAL_BASE_URL` | 门户根地址（无尾斜杠），用于拼接上述两条路径。 |
| `app.b2b.access-url-prefix` / `B2B_ACCESS_URL_PREFIX` | 可选；非空时作为 B2B 分享链接的**完整前缀**（须以 `/` 结尾），覆盖默认 `{portal}/portal/b2b/order/`。 |
| `app.customer-order.public-frontend-base-url` / `JEWELRY_CUSTOMER_ORDER_FRONTEND_URL` | 可选；非空时**仅 C 端进度链接**使用该基址而非 `portal.base-url`（例如 C 端单独域名时再开）。 |

B2B 创建订单接口返回的 `accessUrl`、客户进度接口返回的 `publicPageUrl`、分享卡片二维码内容均与上述约定一致。

## 4. 前端（`b2b-client`）职责

- 路由 `createWebHistory` 与 Nginx `try_files … /index.html` 配合，支持深链打开。
- `OrderDetailView`：仍通过 `GET /api/b2b/order/:token` 拉取 B2B 订单详情。
- `CustomerProgressView`：先请求 `GET /api/public/customer-order/:token/hint` 预填登录/注册表单；登录后绑定 `view_token` 并拉取 `GET /api/portal/c/orders/:orderId/summary` 展示进度。

本地开发：`vite` 已将 `/api` 代理到 `http://localhost:8851`。

## 5. 与管理端（`frontend`）的关系

管理端 **不再**提供独立的公开「客户进度」Hash 路由；设计师/管理员在后台生成的链接应指向 **8852 门户**。管理端继续负责登录后的订单管理与「生成进度链接」操作，仅链接目标改为统一门户。

## 6. 部署检查清单

1. 容器或主机上 **8852** 对外可访问，且 `location /api/` 代理到后端 `8851`（与现有 `b2b-client/nginx.conf` 一致）。
2. 后端环境变量 **`JEWELRY_PORTAL_BASE_URL`** 设为公网门户基址（含 scheme 与端口），否则默认 `http://localhost:8852` 会导致二维码/复制链接不适合外发。
3. 若曾使用 `B2B_ACCESS_URL_PREFIX` 指向旧版 `…/api/b2b/order/`，请改为门户 SPA 前缀（如 `http://主机:8852/portal/b2b/order/`），否则二维码仍指向 JSON API 而非页面。
